# TaskFlow Windows 桌面版 MVP 功能范围规划 v0.1

> 关联文档：`../TaskFlow-任务管理应用项目文档-v1.0.md`（v1.0 全量版本，含四端同步/账号/协作）
> 本文档只定义 **Windows 桌面单机 MVP** 的范围，是 v1.0 的一个严格子集。

---

## 0. 一句话结论

**MVP = 一个关不掉的记事本 + 一个一定会响的闹钟。**

单机运行、免登录、零配置、开机即可用。核心只保证一件事：**用户从「想到」到「记下」不超过 3 秒，关掉程序不丢，到点一定会提醒。**

明确不做：账号体系、云同步、多端、协作、看板/日历视图、AI。

---

## 1. MVP 要验证的唯一假设

> 用户是否愿意长期使用一个「不用注册、打开就能记、到点就响」的桌面待办工具？

围绕这个假设，MVP 只服务于一条主链路和一个典型场景（对应 v1.0 文档场景 A）：

**会议中按 `Ctrl+Alt+N`，输入"周五给张总反馈预算"，回车，继续开会，不再打开主窗口。**

## 2. 成功标准（内测阶段，非商业指标）

| 指标 | 目标 | 说明 |
|---|---|---|
| 次日留存 | ≥ 30% | 验证「会用第二次」 |
| 人均日创建任务 | ≥ 3 条 | 验证录入成本足够低 |
| 快速添加使用率 | ≥ 50% | 验证全局热键确实是主入口 |
| 提醒准时率 | ≥ 99%（±30 秒） | 信任底线，不达标整个产品失效 |
| 崩溃率 | < 0.5% | MVP 阶段可放宽 |

---

## 3. 优先级排序依据（先讲规则，再看清单）

每一项功能按四个维度评估，**不是按"功能大小"排序**：

| 维度 | 判断问题 | 权重 |
|---|---|---|
| **① 闭环性** | 缺了它，用户能否完成「记下 → 看到 → 做完」的最小闭环？ | 最高 |
| **② 上手成本** | 它是否要求用户先配置、先学习、先注册？增加一步就增加流失 | 高 |
| **③ 可后加性** | 后期补做的代价有多大？涉及改数据表/改存储结构的，必须提前 | 高 |
| **④ 实现成本** | 占用多少工期、多少边界情况要处理 | 中 |

**判定规则：**

- 支撑闭环 **且** 零配置 → **P0 必备**
- 只在特定场景有价值、有替代方案 → **P1 延后到 v1.1**
- 纯体验增强、或属于其他品类（番茄钟/习惯打卡） → **P2 暂不做**
- 实现成本高 **但** 后期补做要改数据模型 → 提前做**地基**，功能本身仍可延后

## 4. P0 必备功能清单

### 4.1 A 组：核心闭环（没有它，产品不成立）

| 编号 | 功能 | 用途 | 为什么是 P0 |
|---|---|---|---|
| **M-01** | **任务创建与编辑**<br>标题必填，备注为纯文本，编辑自动保存（防抖） | 产品的原子能力 | 没有任务就没有产品。备注用纯文本而非 Markdown 渲染，省掉编辑器与预览的复杂度 |
| **M-02** | **一键完成 + 5 秒撤销**<br>单击复选框完成，Toast 提供「撤销」 | 完成任务是唯一的正向反馈，也是留存来源 | 完成动作必须一次点击；撤销是防止误触的关键，成本极低但体验收益极高 |
| **M-03** | **清单分组**<br>内置「收件箱」+ 用户自建清单，**只做单层** | 让任务有归处，避免全部堆在一起 | 单层清单已能覆盖 90% 场景；多层文件夹是复杂度黑洞，直接砍掉 |
| **M-04** | **截止日期 + 本地提醒**<br>日期/时间选择，系统原生通知，支持「准时」和「提前 10 分钟」两档 | 待办工具的价值一半在「提醒」 | 提醒是信任基础。只做本地通知（单通道），但**准时率必须做到 99% 以上** |
| **M-05** | **三级优先级**<br>高 / 中 / 低 / 无，颜色标记 + 参与排序 | 帮用户在众多任务中决定先做哪件 | 保留但简化：v1.0 的四级对 MVP 是过度设计，三档足够且选择成本更低 |
| **M-06** | **「今天」视图（默认首页）**<br>今天到期 + 已逾期 + 未排期，三组聚合 | 打开就能看到「现在该做什么」 | 这是产品的第一屏。默认落在「今天」而不是「全部」，直接给出行动指令 |

> **A 组合起来就是完整闭环**：打开 → 看到今天要做什么 → 记一条新的 → 做完勾掉。

### 4.2 B 组：桌面形态必需品（Windows 产品区别于网页的立身之本）

| 编号 | 功能 | 用途 | 为什么是 P0 |
|---|---|---|---|
| **M-07** | **全局热键快速添加**<br>`Ctrl+Alt+N` 唤起迷你输入框，回车即存，`Esc` 关闭，**不打开主窗口** | 捕捉「想到的那一秒」 | 这是与网页版待办的根本差异，也是核心场景 A 的全部价值。实现成本不高（注册全局热键 + 无边框小窗） |
| **M-08** | **本地持久化 + 回收站**<br>SQLite 存储，删除为软删除，保留 30 天可恢复 | 关掉程序不丢数据；误删可救 | 「永不丢失」是承诺。软删除只需一个 `deleted_at` 字段，成本极低 |
| **M-09** | **关键词搜索**<br>`Ctrl+F` 唤起，在全部任务中搜标题与备注 | 任务超过 50 条后，找不到等于不存在 | 一条 `LIKE` 查询即可，投入产出比最高 |
| **M-10** | **系统托盘常驻 + 单实例运行**<br>关闭窗口时最小化到托盘而非退出；重复启动只唤起已有实例 | 保证提醒进程一直活着；避免多实例写库冲突 | 严格说这是**技术必需**而非功能：进程退出 = 提醒失效 = 核心承诺破产 |

### 4.3 附：一个「够用就好」的日期输入

不做完整的自然语言解析（见 5.1 的理由），但在快速输入框里提供：

- 输入框下方 3 个快捷 chip：**今天 / 明天 / 本周五**
- 默认不填日期 → 落入「收件箱」，不打扰用户

这是「自然语言解析」的 10% 成本版本，能拿到 60% 的收益。

## 5. P1 延后到 v1.1（有价值，但 MVP 不做）

| 编号 | 功能 | 用途 | 延后理由 |
|---|---|---|---|
| N-01 | **完整中文自然语言解析**<br>"周五前给张总反馈 #工作 !高" | 进一步降低录入成本 | ⚠️ 关键取舍：解析准确率达不到 90% 时，**错误解析比不解析更伤体验**（用户要先检查再改）。MVP 用 M-07 + 快捷 chip 替代，等真实语料积累后再做 |
| N-02 | **子任务（单层）** | 拆解复杂任务 | 需要改表结构（`parent_id`），但 MVP 数据量小、可平滑加字段，故延后功能、提前预留字段 |
| N-03 | **重复任务**（每天/每周/工作日） | 周会、日报等固定事项 | 涉及 RRULE 解析与下次实例生成，边界情况多（跨时区、闰日），MVP 周期内不划算 |
| N-04 | **标签** | 跨清单的横向分类 | 清单 + 搜索已能覆盖大部分归类需求，属于第二重分类体系 |
| N-05 | **批量操作**（多选后完成/删除/移动） | 清理积压任务 | 单人 MVP 的任务量下，逐条操作成本可接受 |
| N-06 | **数据导出 / 导入（JSON、CSV）** | 换机不丢、退出无锁定 | 单机产品必须有兜底，但 MVP 内测期可先人工备份 `db` 文件 |
| N-07 | **清单内拖拽排序** | 手动调整优先级顺序 | 有「按截止时间/优先级排序」的自动排序兜底，手动排序是锦上添花 |
| N-08 | **开机自启 + 自动更新** | 减少「忘了打开」导致的提醒失效 | 内测阶段手动更新可接受；正式发布前必须补齐 |
| N-09 | **深色主题 / 紧凑视图** | 长时间使用的舒适度 | 纯 UI 层，随时可加，不影响架构 |
| N-10 | **组合筛选与多视图**（最近 7 天 / 已完成 / 按清单） | 更强的信息组织 | 「今天」视图已满足 MVP 的主路径 |

## 6. P2 明确不做（不是"以后再说"，是"这一版产品不做"）

| 类别 | 内容 | 判断 |
|---|---|---|
| 账号与同步 | 注册登录、云同步、多端、设备管理 | 一旦引入账号，MVP 立刻变成 v1.0 规模。**这是本次范围收缩的核心决定** |
| 协作 | 共享清单、任务指派、协作通知 | 需要服务端与权限模型，与"单机免登录"完全冲突 |
| 视图扩展 | 看板、日历、甘特图 | 属于专业 PM 工具范畴，与"三秒记下"的定位无关 |
| 其他品类 | 番茄钟、习惯打卡、统计报表、日记 | 是独立产品，混进来会稀释核心 |
| 重功能 | 附件上传、全文检索、语音输入、AI 任务拆解 | 成本高、依赖外部服务，与桌面单机形态不匹配 |
| 集成 | 邮件、Outlook/Google 日历双向同步 | 需 OAuth 与服务端，v1.2 之后 |

## 7. 三个关键取舍（需要你确认）

**取舍 1：砍掉账号与云同步。**
这是让 MVP 能在一个月内交付的前提，也是"打开就能用"的来源。代价是换机丢数据 —— 用 v1.1 的导入导出兜底。

**取舍 2：自然语言解析不进 MVP。**
它是 v1.0 文档里的核心差异点，但对 MVP 是陷阱：语料库、歧义处理、准确率验证的工作量可能超过其余全部功能之和，且效果不达标时反而增加用户认知负担。**先用热键 + 快捷 chip 拿到 60% 收益，用真实语料养模型，v1.1 再上。**

**取舍 3：提醒只做单通道，但做到极致。**
不做短信/邮件/多端冗余，只用 Windows 系统通知。但必须通过「驻留进程 + 系统计划任务」双保险，保证程序被关掉甚至重启后提醒仍然触发。**宁可功能少，不能提醒失约。**

## 8. 必须提前预留的技术地基

以下内容在 MVP **不做功能**，但数据结构必须留好，否则 v1.1 会返工：

| 预留项 | 原因 | 成本 |
|---|---|---|
| 任务表预留 `list_id`、`parent_id`、`recurrence_rule`、`tag` 关联表 | 加子任务/重复/标签时不必改表 | 几乎为 0，建表时多几个可空字段 |
| 预留 `created_at`、`updated_at`、`version`、`deleted_at` | 将来接同步时的冲突解决依据 | 0 |
| SQLite `schema_version` + migration 机制 | 避免升级时清库 | 半天 |
| 数据访问层与 UI 解耦（Repository 模式） | 将来换成本地+远端双数据源，只改一层 | 半天 |

这四条是「可后加性」这一优先级维度的直接落地：**功能可以延后，接口不能延后。**

## 9. MVP 验收清单（做完才算交付）

- [ ] 冷启动到光标可输入 ≤ 1.5 秒
- [ ] 全局热键唤起 ≤ 150 毫秒，且在其他应用全屏时依然可用
- [ ] 提醒准时率 ≥ 99%（±30 秒），包含"程序已关闭"与"电脑重启后"两种场景
- [ ] 完全断网状态下所有功能可用（含冷启动）
- [ ] 连续录入 20 条任务无卡顿
- [ ] 强杀进程后重新打开，数据零丢失
- [ ] 误删任务可在回收站恢复，30 天自动清理生效

## 10. 里程碑建议（单人开发，约 4 周）

| 周次 | 内容 | 产出 |
|---|---|---|
| W1 | 工程骨架：托盘常驻、单实例、全局热键、SQLite + migration | 能唤起输入框并落库 |
| W2 | 任务 CRUD、清单、今天视图、完成与撤销 | 核心闭环可用 |
| W3 | 截止日期、本地提醒、回收站、搜索 | 承诺兑现 |
| W4 | 打磨：启动速度、快捷键、空状态引导、内测发版 | 可交付内测 |

> 若只能保一件事，保**提醒可靠性**；若能砍一件事，先砍**搜索**。
