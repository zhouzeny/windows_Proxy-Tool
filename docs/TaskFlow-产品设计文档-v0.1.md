# TaskFlow Windows 桌面版 产品设计文档 v0.1

> 范围：Windows 桌面单机 MVP｜配套文档：`TaskFlow-MVP-功能范围规划-v0.1.md`、`../TaskFlow-任务管理应用项目文档-v1.0.md`

---

## 1. 产品概述

**一句话定位**：一个不用注册、打开就能记、到点一定会响的 Windows 桌面待办工具。

**核心价值主张（三条，缺一不可）**

| 主张 | 含义 | 对应的设计约束 |
|---|---|---|
| **三秒记下** | 从"想到"到"记下"不超过 3 秒 | 全局热键 + 单行输入 + 智能默认值 |
| **关掉不丢** | 程序退出、断电、强杀，数据都在 | 本地 SQLite + 每次编辑即时落盘 |
| **到点就响** | 提醒不因程序关闭而失效 | 托盘驻留 + 系统计划任务双保险 |

**产品形态**：Windows 桌面单机应用（本地优先，无账号、无云同步、无网络依赖）。
**后续演进**：v1.1 补齐重复任务/标签/导入导出 → v1.2 接入云同步与多端 → v2.0 轻量协作。

## 2. 目标用户

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **P1 职场个人（主要）** | 25–40 岁知识工作者，日均 15–40 条任务，PC 为主 | 会议/沟通中不遗漏待办，打开就知道先做什么 |
| **P2 学生（次要）** | 课程、作业、考试节点密集 | 按课程归类、到点提醒 |

**非目标用户**：需要甘特图、资源负载、审批流、工时核算的团队与组织 —— 那是专业 PM 工具的领域。

## 3. 设计原则（整体方向的落点）

这五条是后续所有功能取舍的判据，冲突时优先级从上到下。

1. **零配置优先**
   不做登录、不做新手引导、不做初始设置。首次打开直接是一个可以打字的光标。
   任何"先配置才能用"的功能，一律不进 MVP。

2. **热键优先于主窗口**
   最高频的入口是 `Ctrl+Alt+N` 那个小输入框，不是主窗口。
   主窗口用来"回顾"，输入框用来"捕捉"——职责分开。

3. **一个视图回答一个问题**
   「今天」视图只回答"我现在该做什么"，不做多维度筛选面板。
   想找别的东西，用搜索或清单，不要在主屏堆功能。

4. **默认值即合理**
   不填日期 → 进收件箱；不选优先级 → 无；不选清单 → 收件箱。
   **永远不因为用户没做选择而阻塞保存。**

5. **所有破坏性操作都可逆**
   删除 → 回收站（30 天）；完成 → 5 秒撤销；编辑 → 自动保存且不覆盖。
   用户敢点，产品才敢用。

## 4. 核心使用场景

**场景 A｜会议中捕捉（主场景）**
正在开视频会议，想到"周五要给张总反馈预算方案"。按 `Ctrl+Alt+N`，输入标题，点一下「本周五」chip，回车。输入框消失，会议窗口还在前台，全程不到 3 秒。

**场景 B｜早上开机看今天**
开机后 TaskFlow 在托盘自动运行。点托盘图标，第一屏就是「今天」：逾期 2 条、今天到期 4 条、未排期若干。花 10 秒决定先做哪件。

**场景 C｜下班前清理**
勾掉做完的几条，剩下没做完的用右键"改到明天"。误勾了靠左下角 Toast 撤销。

**场景 D｜到点提醒**
20:00 有提醒，此时主窗口已关闭、只剩托盘。系统通知准时弹出，点击通知直接定位到该任务。

## 5. 功能设计

### 5.1 功能结构

```
TaskFlow
├─ 任务（核心）
│  ├─ 创建 / 编辑 / 完成 / 删除 / 恢复
│  ├─ 标题、备注、截止时间、优先级、所属清单
│  └─ 快速添加（全局热键）
├─ 清单（组织）
│  └─ 收件箱 / 自建清单 / 已完成（只做单层）
├─ 视图
│  ├─ 今天（逾期 + 今日 + 未排期）
│  └─ 搜索
├─ 提醒（承诺）
│  ├─ 截止时间
│  └─ 系统通知（准时 / 提前 10 分钟）
└─ 系统（形态）
   ├─ 托盘常驻 + 单实例
   ├─ 本地存储 + 回收站
   └─ 基础设置（提醒方式、开机自启）
```

### 5.2 P0 功能清单（MVP 交付范围）

| 模块 | 功能 | 关键交互 | 设计要点 |
|---|---|---|---|
| 任务 | 创建与编辑 | 单行输入 → 回车保存；详情面板编辑全部字段 | 备注用**纯文本**，不做 Markdown 渲染，省掉编辑器复杂度 |
| 任务 | 完成与撤销 | 单击复选框；底部 Toast「已完成 · 撤销」5 秒 | 完成是唯一的正向反馈，必须零摩擦 |
| 任务 | 删除与恢复 | Delete 键 → 回收站；30 天后自动清理 | 软删除，界面上明确告知"可在回收站找回" |
| 清单 | 分组 | 左侧栏：今天 / 收件箱 / 各清单 / 已完成 | **只做单层**，不做文件夹嵌套 |
| 视图 | 今天 | 三段聚合：已逾期 → 今天到期 → 未排期 | 逾期用红色日期标记，但不弹窗打扰 |
| 视图 | 搜索 | `Ctrl+F`，搜标题与备注，跨清单 | 输入即搜，无需回车 |
| 提醒 | 截止与通知 | 日期时间选择器；下拉选「准时」或「提前 10 分钟」 | 通知可点击直达任务 |
| 优先级 | 三级标记 | 高（红）/ 中（黄）/ 低（蓝）/ 无 | 只做颜色点标记，不做文字标签，减少视觉噪音 |
| 快速添加 | 全局热键 | `Ctrl+Alt+N` → 无边框小窗 → 回车保存，`Esc` 取消 | 小窗内提供「今天 / 明天 / 本周五」三个 chip |
| 系统 | 托盘与单实例 | 关闭窗口 → 最小化到托盘；重复启动 → 唤起已有实例 | 托盘右键菜单：打开 / 快速添加 / 退出 |

### 5.3 P1 功能（v1.1）

中文自然语言解析（"周五前给张总反馈 #工作"）｜子任务（单层）｜重复任务（每天/每周/工作日）｜标签｜批量操作｜JSON/CSV 导入导出｜清单内拖拽排序｜开机自启与自动更新｜深色主题｜组合筛选与更多视图。

### 5.4 P2 明确不做（本版本不做）

账号与云同步｜多端｜协作共享清单｜看板/日历/甘特视图｜番茄钟/习惯打卡/统计报表｜附件与全文检索｜AI 任务拆解｜语音输入｜邮件与日历集成。

> 判断依据：凡需要服务端、需要权限模型、或属于其他品类的能力，都不进入 MVP。

## 6. 界面结构

**主窗口（约 900 × 620，可缩放）**

```
┌──────────┬────────────────────────────────┐
│ 今天    ●│  今天                    🔍  ⚙  │
│ 收件箱  3│ ──────────────────────────────  │
│ ──────── │  已逾期                        │
│ 工作    5│  ○ 提交报销单        10-29 ⚠   │
│ 生活    2│  今天到期                      │
│ ──────── │  ○ 给张总反馈预算  18:00 !     │
│ 已完成   │  ○ 整理季度复盘                │
│          │  未排期                        │
│          │  ○ 看《深度工作》第三章         │
│          │                                │
│          │  + 添加任务…                   │
└──────────┴────────────────────────────────┘
```

**快速输入浮窗（居中，约 560 × 120）**

```
┌────────────────────────────────────┐
│  给张总反馈预算方案 ✏              │
│  [今天] [明天] [本周五]   ⏰ 优先级  │
└────────────────────────────────────┘
```

**关键快捷键**

| 快捷键 | 动作 |
|---|---|
| `Ctrl+Alt+N` | 全局唤起快速添加 |
| `Ctrl+N` | 主窗口内新建任务 |
| `Enter` | 保存并继续输入下一条 |
| `Space` | 完成 / 取消完成选中任务 |
| `Delete` | 删除到回收站 |
| `Ctrl+Z` | 撤销上一步 |
| `Ctrl+F` | 搜索 |
| `Esc` | 关闭浮窗 / 退出编辑 |

## 7. 数据模型（MVP 精简版）

| 实体 | 主要字段 |
|---|---|
| **Task** | `id`、`list_id`、`parent_id`(预留)、`title`、`note`、`status`、`priority`、`due_at`、`remind_offset`、`completed_at`、`created_at`、`updated_at`、`deleted_at`、`version` |
| **List** | `id`、`name`、`sort_order`、`is_inbox`、`created_at` |
| **Setting** | `key`、`value`（提醒方式、开机自启、窗口位置等） |

**存储**：本地 SQLite，单文件，用户目录下 `%APPDATA%\TaskFlow\taskflow.db`；带 `schema_version` 与 migration 机制。

> `parent_id` / `version` / `deleted_at` 在 MVP 中不产生业务功能，但必须建好 —— 为 v1.1 的子任务和 v1.2 的同步省掉改表工作。

## 8. 非功能要求

| 类别 | 要求 |
|---|---|
| 启动速度 | 冷启动到光标可输入 ≤ 1.5 秒 |
| 响应速度 | 热键唤起 ≤ 150ms；1000 条任务下列表滚动不掉帧 |
| 提醒可靠性 | 准时率 ≥ 99%（±30 秒），覆盖"程序已关闭""电脑重启后"两种情况 |
| 离线可用 | 完全断网时 100% 功能可用 |
| 数据安全 | 强杀进程不丢数据；每日自动备份一份 db 文件，保留 7 天 |
| 资源占用 | 常驻内存 ≤ 120MB，空闲 CPU ≈ 0 |
| 系统兼容 | Windows 10 1809 及以上、Windows 11 |

## 9. MVP 验收标准

- [ ] 首次打开无需任何配置即可创建任务
- [ ] 会议场景下按热键 → 记一条 → 回到会议，全程 ≤ 3 秒且主窗口未打开
- [ ] 关闭窗口后提醒仍准时触发；重启电脑后提醒仍准时触发
- [ ] 删除的任务可在回收站找回；完成的任务可 5 秒内撤销
- [ ] 断网、强杀进程、系统重启后数据零丢失
- [ ] 全部 P0 功能有对应测试用例并通过

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 提醒被系统拦截（勿扰模式、通知权限） | 核心承诺失效 | 首次运行检测通知权限；被拦截时在窗口内显式告警 |
| 单机产品换机丢数据 | 用户流失 | MVP 提供 db 文件手动备份指引，v1.1 上导入导出 |
| 无同步导致多设备用户不满足 | 目标用户覆盖不足 | 明确 MVP 只服务"单一 PC 为主"的用户，不承诺多端 |
| 任务堆积后「今天」视图失去重点 | 产品价值下降 | 逾期任务折叠显示，超过 10 条提示"建议先清理" |
